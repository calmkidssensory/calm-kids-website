CALM KIDS SENSORY — FREE SAMPLER EMAIL CAPTURE
Google Sheets + Apps Script setup

This is the backend for the "3-Page Free Sampler" forms on our book pages
(website/books/*.html, wired up by website/js/sampler-form.js). It logs every
request to a Google Sheet and sends the visitor a cozy, brand-styled HTML
email with their sampler download and the book's cover art.

The script below is the single source of truth for every book's file paths
and Amazon link — it does not trust anything the browser sends except the
visitor's email and which book they asked for. This is what keeps download
links from ever going stale or 404ing: the URLs are built from the same
slug-based naming convention the website itself uses, not copied by hand.

------------------------------------------------------------
STEP 1 — Create the Sheet (skip if you already did this)
------------------------------------------------------------
1. Go to sheets.google.com and create a new, blank spreadsheet.
2. Name it something like "Calm Kids Sensory — Sampler Requests".
3. Rename the first tab (bottom-left) to "Requests" if you'd like — the
   script below works with whatever the active sheet is, so this is optional.

------------------------------------------------------------
STEP 2 — Add the Apps Script
------------------------------------------------------------
1. In the sheet, open Extensions > Apps Script.
2. Delete any existing code in Code.gs and paste in EVERYTHING between the
   dashed lines below (this replaces the earlier plain-text version).
3. Click the save icon (or Ctrl+S / Cmd+S).
4. From the function dropdown at the top, choose "setupSheetHeaders" and
   click Run once. This writes the column headers into row 1. If this is
   your first time running the script, you'll be asked to authorize it —
   approve it (you'll see an "unverified app" warning since this is your
   own private script; click Advanced > Go to (project name) to continue).

If you already authorized the earlier version of this script, you do not
need to authorize again — the permissions (Sheets + Gmail send) are the same.

// One-time helper: run this manually from the Apps Script editor to write
// the header row. Safe to re-run — it only touches row 1.
function setupSheetHeaders() {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  sheet.getRange(1, 1, 1, 5).setValues([
    ["Date", "Email", "Book", "Sampler PDF", "Amazon Link"],
  ]);
}

function doPost(e) {
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();

  var email = (e.parameter.email || "").trim();
  var slug = (e.parameter.slug || "").trim();
  var book = BOOKS[slug];

  if (!email || !book) {
    return ContentService
      .createTextOutput(JSON.stringify({ status: "error", message: "Missing email or unknown book" }))
      .setMimeType(ContentService.MimeType.JSON);
  }

  // Built from the site's own naming convention, not from anything the
  // browser sent — this is what guarantees the links never 404.
  var pdfUrl = SITE_URL + "/pdf/" + slug + "-sampler.pdf";
  var coverUrl = SITE_URL + "/images/covers/" + slug + ".jpg";
  var amazonUrl = book.amazonUrl || AMAZON_AUTHOR_URL;

  sheet.appendRow([new Date(), email, book.title, pdfUrl, amazonUrl]);

  sendSamplerEmail(email, book.title, coverUrl, pdfUrl, amazonUrl);

  return ContentService
    .createTextOutput(JSON.stringify({ status: "ok" }))
    .setMimeType(ContentService.MimeType.JSON);
}

function sendSamplerEmail(email, title, coverUrl, pdfUrl, amazonUrl) {

    amazonUrl +
    "\n\n" +
    "We hope they bring a little quiet, screen-free focus to your day.\n\n" +
    "Warmly,\n" +
    "Calm Kids Sensory\n\n" +
    "Connect With Us:\n" +
    "YouTube: Calm Kids Sensory\n" +
    "Amazon Author Page, PikMe Publishing: " + AMAZON_AUTHOR_URL + "\n" +
    "Instagram: @calmkidssensory\n" +
    "TikTok: @calmkidssensory\n" +

    name: "Calm Kids Sensory",

  });
}

STEP 3 — Deploy the update
------------------------------------------------------------
If this is your FIRST deployment, follow these deploy steps as normal:
1. Deploy > New deployment > gear icon > "Web app".
2. Execute as: Me. Who has access: Anyone.
3. Click Deploy, approve the authorization prompt, and copy the Web app URL.

If you already have a LIVE deployment (you're updating the earlier script):
saving the code alone does NOT update the live /exec URL — you must publish
a new version:
1. Deploy > Manage deployments.
2. Click the pencil (edit) icon on your existing deployment.
3. Under "Version", choose "New version".
4. Click Deploy.
The Web app URL stays exactly the same — nothing to change in
website/js/sampler-form.js this time.

------------------------------------------------------------
NOTES
------------------------------------------------------------
- The website sends the request with mode: "no-cors", which is a known
  limitation of Google Apps Script Web Apps not sending browser-readable CORS
  headers. This means the site cannot read Google's response and shows the
  success message as soon as the request leaves the browser. If you want to
  confirm delivery, check the sheet directly.
- Nothing in this file needs to be uploaded anywhere — it's a reference copy
  of the script that lives on Google's side once deployed.

------------------------------------------------------------
TROUBLESHOOTING — rows appear in the sheet but no email arrives
------------------------------------------------------------
This means the script hasn't been granted permission to send mail yet. Apps
Script only asks for the permissions a function actually touches the first
time you run it, and running setupSheetHeaders alone (Sheets access only)
does not trigger the Gmail-send permission prompt.

Fix:
1. In the Apps Script editor, from the function dropdown choose "doPost".
2. Click Run. It will fail immediately with a small "e is not defined"
   error — that's expected and fine, doPost needs a live request to run
   properly. What matters is that clicking Run surfaces an "Authorization
   required" prompt first.
3. Click through it: Review permissions > pick your account > Advanced >
   Go to (project name) > Allow. Make sure the Gmail send permission is
   included in what you approve, not just Sheets.
4. No redeploy needed — this authorization applies immediately to the
   existing Web App deployment. Test a sampler form on the site again.

------------------------------------------------------------
TROUBLESHOOTING — sampler link in the email 404s
------------------------------------------------------------
As of this version, the script builds pdfUrl and coverUrl itself from the
book's slug rather than trusting the browser, so this shouldn't happen
again. If it still does:
1. Confirm the slug in the BOOKS map exactly matches the actual filename
   under website/pdf/ (case-sensitive, hyphens included).
2. Confirm you published a "New version" after editing the code (see
   Step 3) — editing alone doesn't update the live URL.
3. Give GitHub Pages a minute after a push; the CDN can briefly serve a
   cached 404 for a just-added file.
